# CI and Status Badges

Mirrors the setup in [`peterclark/pointing.page`](https://github.com/peterclark/pointing.page):
badge data is generated by our own workflows and published to an orphan branch,
so there is no third-party coverage service, no external account, and no secret
beyond the built-in `GITHUB_TOKEN`.

## Workflows

| Workflow | File | Trigger | What it does |
| --- | --- | --- | --- |
| **CI** | `.github/workflows/ci.yml` | push to `main`, every PR | Lint, tests with coverage, production build; writes a coverage table to the run summary and uploads `coverage/` as an artifact (14-day retention) |
| **Badges** | `.github/workflows/badges.yml` | after CI completes on `main` | Publishes shields.io badge JSON to the orphan `badges` branch |

CI runs as a single job — this is a small front-end app with no backend, no
secrets, and no services to stand up, so splitting it into parallel jobs would
cost more in repeated `npm ci` time than it saves.

## How the badges work

After CI finishes on `main`, the Badges workflow:

1. Downloads the `coverage` artifact from the CI run that triggered it.
2. Runs `scripts/coverage-badge.mjs`, which turns `coverage-summary.json` into
   [shields.io endpoint JSON](https://shields.io/badges/endpoint-badge) with a
   colour picked from the line-coverage percentage.
3. Writes a matching `build.json` from that CI run's conclusion.
4. Commits both to the orphan `badges` branch.

shields.io then renders the badge by reading those files' raw URLs.

To regenerate the coverage badge locally:

```bash
npm run test:coverage
node scripts/coverage-badge.mjs   # writes badges/coverage.json
```

Both `coverage/` and `badges/` are gitignored — they are build output, and on
CI they travel as an artifact and a branch respectively.

## Coverage scope

`vite.config.js` sets what counts (`src/**/*.{js,jsx}`) and what does not: test
files, the Vitest setup helper, and `src/main.jsx` (an entrypoint that only
mounts the app). No thresholds are enforced — the suite currently sits near 98%
line coverage, and a failing threshold on an unrelated PR is noise rather than
signal. Add thresholds if that stops being true.

## ⚠️ This repository is private

shields.io and GitHub's own badge endpoint fetch badge data **anonymously**.
While `peterclark/battledeck` is private, both `raw.githubusercontent.com` and
the workflow badge SVG return 404 to anyone not signed in as you — so the
badges render broken for everyone else.

### Option A — make the repository public

Nothing else changes; both badge URLs start working immediately.

### Option B — stay private, publish badge data to a public gist

Badge JSON is not sensitive, so it can live in a public gist even when the code
does not.

1. Create a **public** gist containing `coverage.json` and `build.json`
   (any placeholder content).
2. Add two repository secrets: `GIST_ID` (the gist's hash) and `GIST_TOKEN`
   (a fine-grained PAT with **Gists: read and write**).
3. Add a step to `.github/workflows/badges.yml` that PATCHes the gist:

   ```yaml
   - name: Publish badge data to gist
     if: env.GIST_TOKEN != ''
     env:
       GIST_TOKEN: ${{ secrets.GIST_TOKEN }}
       GIST_ID: ${{ secrets.GIST_ID }}
     run: |
       payload=$(node -e '
         const fs = require("node:fs");
         const files = {};
         for (const f of ["coverage.json", "build.json"]) {
           files[f] = { content: fs.readFileSync("badges/" + f, "utf8") };
         }
         process.stdout.write(JSON.stringify({ files }));
       ')
       curl -sSf -X PATCH \
         -H "Authorization: Bearer $GIST_TOKEN" \
         -H "Accept: application/vnd.github+json" \
         -d "$payload" \
         "https://api.github.com/gists/$GIST_ID" > /dev/null
   ```

4. Point the badge URLs at
   `https://gist.githubusercontent.com/peterclark/$GIST_ID/raw/coverage.json`,
   and swap the CI badge for the same endpoint style reading `build.json`
   (the workflow SVG stays private-only):

   ```markdown
   [![Build](https://img.shields.io/endpoint?url=https%3A%2F%2Fgist.githubusercontent.com%2Fpeterclark%2F$GIST_ID%2Fraw%2Fbuild.json)](https://github.com/peterclark/battledeck/actions/workflows/ci.yml)
   ```

## First run

The `badges` branch does not exist until the Badges workflow runs for the first
time on `main`. Until then the coverage badge shows shields.io's "invalid
response" state — that is expected, not a misconfiguration.
